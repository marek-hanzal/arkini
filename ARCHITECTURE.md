# Arkini architecture

This is the canonical map of implemented ownership and lifecycle. It does not catalog routes, fields, UI tuning, or future work. Gameplay meaning belongs to [`GAME.MD`](GAME.MD), authoring to [`CONFIG.md`](CONFIG.md), and persisted-format compatibility to [`VERSION.md`](VERSION.md).

Production modules use the flat topology `src/<domain>/<type>/<file>`. The domain names one semantic owner and the type directory names the code grammar, such as `fn/`, `fx/`, `ui/`, `schema/`, `error/`, `service/`, `layer/`, or `atom/`; production code does not add directories below that grammar layer. An independently useful policy, lifecycle, or capability is either an exact module in its current owner or, when it has a real public contract and dependency direction, a hyphenated top-level domain. File count and visual grouping never justify a micro-domain or another directory. The only structural exceptions are URL topology under `src/@routes` and root, process, CLI, worker, or static composition entrypoints that cannot belong to a grammar directory. Cross-root imports use configured path aliases; relative imports stay inside their local ownership tree and never climb through repository roots. Behavior tests mirror `test/<domain>/<type>/` when they exercise grammar-owned production code; process and route integration suites may instead mirror their structural owner. Reusable test helpers stay flat in `test/support/` or one domain-owned `support/` layer, while a neighboring `Foo.test/` directory may hold non-trivial fixtures for that one test. Test and test-only support never live under `src/`. One cohesive owner keeps private support declarations in its file, and no layer hides them in a catch-all barrel or `types.ts` pile.

Semantic ownership is not access control. Any product owner may directly consume another owner's well-designed component, pure operation, schema, type, or capability when the contract fits and the dependency follows the declared direction. Independently useful responsibilities should be visible as shallow semantic roots with standard grammar, not buried to preserve territorial privacy. Do not duplicate behavior or introduce forwarding APIs, adapters, wrappers, or umbrella modules merely because an exact implementation lives in another domain; enforce the real side-effect and dependency boundaries instead.

- The production pipeline has explicit semantic roots. `src/production-condition` owns authored runtime condition evaluation. `src/production-output` owns output, drop, and roll contracts/resolution, including the private zero-to-one probability policy for Chance rolls, plus their generic projection vocabulary and presentation; Item Detail supplies its own reference-navigation rendering. `src/production-action` owns immediate action admission, remaining-charge reads, typed charge rejection, and charge settlement. `src/production-input` owns line-input contracts, material planning, buffering, autofill, withdrawal, and storage mutation. `src/production-line` owns line definitions, rule interpretation, reads, and run planning, including the private positive-number policy for runtime multipliers. `src/production-job` owns FIFO queue admission, active-job state, output-capacity reservation, start/completion/cancellation sequencing, and job checks; its isolated `ui/` leaf presents active-job runtime without owning commands. `src/production-delivery` owns outbound allocation, fixed-step travel advancement, validation, reconciliation, and settlement. These roots follow the semantic import map in this contract; Dependency Cruiser enforces only stable graph-wide directions rather than exact current consumers. Callers import exact owners directly.
- `src/game-runtime` owns the canonical live aggregate: Runtime and committed-transition schemas, persisted Cheat state, derived Item purity and generic stateful-operation rejection, the total instant-gameplay predicate, runtime validation, live identity creation/revision/removal, aggregate reads and guards, the single mutable store, and atomic mutation publication. `CommittedTransition` remains here because one transaction owns its current and bounded previous Runtime snapshots together with the ordered committed events. Item Interaction, Game Tick, Cheat commands, persisted State/save, renderer lifecycle, routes, and Electron may consume Game Runtime but Game Runtime cannot import any of them.
- `src/game-persistence` owns canonical serializable State schemas, Runtime projection and hydration, the strict Arkini-save codec, renderer save storage, Runtime autosave coordination, and the exact Electron/filesystem transport adapters. It depends on Game Runtime and explicit durable-data leaves; the dependency never reverses. Game Session, installed-game, Board scenario, game-menu, and Electron main remain composition consumers rather than persistence subdomains.
- `src/simulation-time` owns the immutable fixed simulation quantum that aligns time-aware gameplay values with authoritative step boundaries. Game Tick, Delivery, temporary-item lifecycle, and Instant settlement consume this upstream value contract; it imports no runtime or lifecycle owner.
- `src/game-tick` owns the transient Tick clock cursor, at-most-once elapsed budget, canonical fixed-step replay, job/delivery/temporary advancement order, stable-runtime fast-forward proof, and the scoped production loop. It consumes the Simulation Time quantum and orchestrates Delivery, Job, and temporary-item lifecycle without reverse imports from those owners. Its runtime transaction and layer depend on Game Runtime; the dependency never reverses. Session composition, persisted State/save, renderer lifecycle, and presentation remain outside this root.
- `src/temporary-item` owns fixed-step duration advancement, deterministic expiry-output resolution, expected placement-block admission, and the atomic remove/place expiry transition. Its two public Effects are consumed by Game Tick; operation-local transition and random helpers remain private, and the owner never imports Tick clock, replay, or loop implementation.
- `src/item-interaction` owns captured drop intent/results under `type/`, shared explicit-input drop and stack policy under `fn/`, typed rejection contracts under `error/`, and preview, commit, Inventory release, stack split, explicit removal, and ordinary single-click reads under `fx/`. Preview is advisory; every serialized commit revalidates against the current Runtime and publishes only one complete transition. The individual commit Effects remain separate files because each owns a distinct serialized mutation and rejection lifecycle; they do not justify a deeper `drop/` subtree. Placement and merge execution stay in their exact upstream owners, production commands stay with production, and Item Interaction never owns Runtime schemas/store/checks, immutable Item definitions, Tick, presentation, routes, or Electron.
- `GameConfigFx` belongs to `src/game-config/context` as the upstream loaded-config capability consumed directly by Runtime, validation, placement, and session composition. `GameRuntimeLayerFx` builds that config plus one `SubscriptionRef<CommittedTransition>` and the `RuntimeFx`/`CommittedTransitionsFx` projections of the exact store. It can create a fresh Runtime or accept an already hydrated Runtime value without knowing persisted State. `src/game-session` owns `GameSessionLayerFx`, package-independent Runtime/Tick/save execution, transition subscriptions, first-failure publication, command admission, and disposal; it composes runtime → Game Tick → scoped loop. Deterministic tests compose the same runtime and Game Tick layers from `test/support`; there is no production test façade.
- `src/game-start` owns the public initial-state schemas, exact Board/Inventory/Toolbar placement planning, and the one atomic empty-runtime start transaction. Planning applies Board, then Inventory, then Toolbar entries through canonical placement against one evolving candidate and commits only the completely valid runtime.
- `src/game-event` owns the strict committed-event vocabulary, ordered transient batches, and exact projection of already-applied placement results. ## Canonical game truth

Arkini has three forms:

```text
GameConfig → validated static definition
Runtime    → live gameplay snapshot
State      → serializable gameplay state
```

Game Runtime's one `SubscriptionRef<CommittedTransition>` owns the current runtime, mutation serialization, and gap-free publication:

```text
CommittedTransition { sequence, previousRuntime, runtime, events }
```

`runtime` is current gameplay truth. The monotonic `sequence`, bounded previous snapshot, and events belong to that exact commit and let consumers order and compare presentation without maintaining another writable Runtime.

Every production write enters `modifyRuntimeFx`:

```text
resolve live facts inside the write boundary
→ plan against one pinned snapshot
→ build an immutable candidate
→ validate the complete candidate
→ commit runtime and its events once
```

Waiting and planning remain interruptible. Failure, defect, interruption, or an unchanged event-free result commits and publishes nothing. A successful transition makes runtime truth visible immediately; events describe that same commit and are never a second store.

Independent commands may run concurrently until their short mutation-planning section. Do not add an outer command queue, second semaphore, second current-value/sequence authority, event bus, deep-clone layer, or event-derived read model.

Subscribers own current-plus-tail observation. Runtime listeners ignore event-only transitions; event listeners receive only later batches, never historical replay. Slow external callbacks are isolated and may lag without delaying engine truth, Tick, save, or other listeners. A callback failure is observed independently after the triggering commit: it cannot roll back or stall that commit or peer delivery, but it enters the existing fatal session fail-stop.

[`GAME.MD`](GAME.MD) owns Tick, queues, inputs, charges, placement, merge, and other gameplay semantics.

On fatal failure it best-effort renders a linked thematic text incident beside the exact Arkpack and latest committed save. `RendererRuntime` contains one scoped installed-game resource service. Acquisition uses scoped leases: same-package callers share one provisional result, the explicit load action adopts that exact lease, and `/game/$packageId` exposes only the adopted matching package through route context. With a game, `/game/$packageId/action/exit` owns one best-effort final save/disposal and reports completion to Electron after its terminal presentation settles; without a game, close acknowledges directly. Project publication, refresh, scenario restore, and route release discard the prior session before publishing a replacement. Installed and Editor games never share lifecycle ownership.

Shutdown order for a session is: reject commands, stop Tick, close session scopes, flush the latest stable Runtime when applicable, then dispose its runtime. Concurrent cleanup callers join the same attempt. A failed ordinary final save freezes the session for an explicit retry; destructive reset/editor replacement uses discard-only disposal.

Checkout replaces the current tree, scenarios, and head atomically while Notes remain outside Versions. Scenarios are explicit versioned State snapshots, never autosave. Estimate is a disposable optimistic analysis over the authored acquisition graph. Flow compiles bounded per-output and correlated joint-output quantity distributions; Estimate uses bounded expected first-hitting time, so indivisible deterministic batches round up and stochastic outputs retain their authored probability. It selects a deterministic complete route set by quantity-aware upstream critical-path cost with stable route identity as the tie-break, then bounds alternative refinement where finite roots or co-products invalidate that locally ranked selection; it is not an exhaustive combinatorial optimizer. Demand closure uses the larger of total additive consumed demand and any selected route's concurrent consumed-plus-reusable requirement; reusable one-time and ongoing prerequisites are shared by maximum. It credits finite authored roots once across the witness and charges a jointly selected co-product operation once. The immutable witness selects at most one route per acquired fact and projection normalizes it into a fact DAG whose independent branches overlap in the optimistic critical path. Unsupported bounded distribution state space returns partial instead of inventing a scalar result. Estimate diagnoses cycles and dead ends, but does not evaluate runtime rule truth, placement, concrete item identity packing, renewable capacity, or engine execution and is never an engine-valid witness. Editor entry warms one immutable Estimate revision in the background; Estimate surfaces capture the current revision when entered and never combine its result with a later config or trigger recalculation merely because that project is saved. Dependencies flow from `src/estimate/fn` and `src/estimate/type` to `src/flow`; these platform-neutral layers do not import UI, renderer, routes, or Electron. `src/estimate/fn` owns query, filter, sort, and selection before React renders results. Flow is likewise an authored graph projection, not gameplay truth.

## Hosted validation and delivery

`Argcfile.sh` owns every repository and packaging command; GitHub workflows only install the pinned toolchain and invoke those commands. Working branches run the complete repository gate once on hosted Linux. macOS and Windows run the focused platform boundary gate: the production build, explicit Community Arkpack verification, and real filesystem, Electron, Arkpack artifact/CLI, Game source, and schema-writer tests. Pure engine, domain, and UI behavior is not repeated per operating system. `main` is the intentional passive escape hatch. Prerelease tags repeat those gates before delivery; stable tags deliberately skip them. Both tag channels then build and sign one canonical Arkpack before macOS arm64, Windows x64, Linux x64, and Linux arm64 jobs embed and byte-compare that same file. Production packages omit source maps; incident diagnostics and exact replay are the supported debugging surface. Both publish a GitHub Release containing those native packages and the same standalone Arkpack; prerelease tags mark it as a prerelease.
