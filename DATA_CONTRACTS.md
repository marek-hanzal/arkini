# External data contracts

Arkini is the only application format version. Its value comes from `package.json` and is embedded only where a file must prove which Arkini build wrote it. Gameplay compatibility is the project-owned `version`; Editor revisions are monotonically increasing project mutations.

`format`, `formatVersion`, namespaces, duplicated path identities, and fixed-value metadata do not belong in Arkini-owned data. `$schema` and schema `$id` are JSON Schema links, not format-version fields.

## Portable game project

| Path | Fields | Contract |
| --- | --- | --- |
| `project.json` | `arkini`, `revision` | Writer identity and current Editor revision. |
| `schema.json` | JSON Schema with stable `$id` and explicit definition references | Exact authoring contract generated by the current engine. |
| `game.json` | `$schema`, `version`, game config except `items` | Project-owned gameplay compatibility plus root config. |
| `items/<type>/<uid>.json` | `$schema`, `item` | The path owns UID and type; the item owns its gameplay ID. No one-entry record wrapper. |
| `resources/<id>.png`, `assets/<id>.png` | PNG bytes | Path owns ID and kind; MIME is fixed by the `.png` contract. |

The compiler rejects a path whose decoded UID or type disagrees with the item. The root config ID is the package ID everywhere downstream.

## Editor sidecars

| Path | Fields | Contract |
| --- | --- | --- |
| `notes/<noteId>.json` | `content`, `createdAtMs`, `updatedAtMs` | Filename owns note ID; timestamps support ordering and conflict-free edits. |
| `scenarios/<hash>.json` | `name`, `revision`, `version`, `save`, timestamps | Filename is a content-safe name hash, so human-readable `name` must remain. Revision and version prove restore compatibility. |
| `versions/head.json` | `current`, `versions` | Publication pointer and ordered history. |
| `versions/<versionId>/version.json` | parent, subject/body/tag, `arkini`, `version`, `sourceRevision`, `contentFingerprint`, `createdAtMs` | Directory owns version ID. Provenance and fingerprint detect stale or corrupted history. |
| `versions/<versionId>/manifest.json` | hashes for game, items, resources, assets, scenarios | Immutable content-addressed snapshot. Length-free because object boundaries are filesystem paths. |
| Editor catalog | root, ownership, timestamps | Local index needed to discover projects without opening every project tree. Project title and version are read from the project itself. |

Editor domain objects may use longer names such as `projectRevision`, `arkpackVersion`, and `versionId` internally when that removes ambiguity. Those names are not repeated in path-scoped files.

## Built and runtime artifacts

| Artifact | Fields | Contract |
| --- | --- | --- |
| `.arkpack` manifest | `version`, `arkini`, config byte `length`, resources `{ id, length }` | Lengths are required to slice the binary stream. Package ID comes from `config.meta.id`; resource MIME is always `image/png`. |
| `.arksig` | Raw padded base64 Ed25519 signature | A detached signature is one value, not a one-property JSON object. A new signing key produces a new trusted Arkpack pair. |
| Editor build descriptor | `projectId`, `revision`, `contentHash`, `signed`, `size`, diagnostics | Filenames derive from project ID; project version and Arkini version already have authoritative owners. |
| `.arksave` | `version`, `arkini`, `state` | Gameplay compatibility, writer identity, and complete runtime state. The file extension already supplies the namespace. Minor project versions remain load-compatible; major versions are breaking. |

Editor Save as and Install publish a signed build as the complete `.arkpack` + `.arksig` pair. Both paths use the same rollback-safe writer; an unsigned replacement removes a stale signature instead of preserving a mismatched sidecar.

## Other persisted or exposed data

Preferences are individual schema-validated scalar JSON files and need no envelope. Diagnostics are JSONL owned by the logging library. MCP OAuth records use the OAuth library's protocol fields; Arkini does not add a format marker. MCP tool input/output schemas and exported game schemas use explicit stable schema IDs so references are never anonymous or resolved as `any`.

When adding an external field, its owner and a reader that cannot derive it must both be identifiable. Otherwise, leave it out.
