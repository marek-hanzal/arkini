# Serakki 0.5.0

Build production chains, move supplies between spaces, and let your machines do the work. This first release brings the offline game and its Editor together, so you can play, make your own world, and share it in one package.

## For players

### Keep things moving

- Queue up production and watch materials travel to where they're needed. Work starts once they arrive. If one request is blocked, later work can go ahead.
- Click to use an item or start its default production line. `Ctrl + left click` fills its queue. Cancel one waiting request or clear the queue to release unused materials; queue order is automatic.
- Cancel an active job when you need to stop long-running work. It produces nothing, consumed materials and spent uses stay spent, and borrowed items return. If returns cannot fit, cancellation leaves the job unchanged.
- Clock items can work automatically, last for a limited time, or both. Choose manual and automatic production separately; some items are automatic-only.
- Tools, deposits, and other items can have limited uses, stock, or health. Uses are spent when work starts, not when you queue it. Merging can spend uses too.
- Some recipes consume their materials; others borrow them and return them afterward. Watch out for expiring ingredients: if one expires during a job, that job produces nothing and spent uses aren't refunded.
- Timers keep running in Inventory, on the Toolbar, and while materials travel or sit inside production. Moving an item into storage won't preserve it forever. Production itself pauses off the Board.
- When an item's lifetime ends, it can finish eligible work before disappearing, or use a Kill switch that stops immediately. A Kill switch may discard returns that no longer fit.

### Inspect and manage production

- Right click an item to open its detail. Info shows storage, stack size, the item limit, and remaining uses. Items with production open Lines, or Queue when work is already running or waiting; items without production show only Info.
- In Lines, choose what to make and set the default recipe. Rule-disabled lines are dimmed and show the first blocking rule's hint when it has one; hidden lines disappear smoothly.
- See which materials are delivered, partly filled, or unavailable. Click an empty material slot to bring that specific ingredient through Autofill, or click stored material to withdraw one piece. Partly filled slots do not trigger targeted Autofill.
- Queue keeps the active job in a reserved slot above waiting requests and shows their material inputs. Recipe artwork helps you recognize the work, and fills with color as the job advances. Transitions show when waiting work becomes active.
- Job countdowns use readable durations; stored ingredients with running timers show a circular clock. If the inspected item disappears, its last detail stays visible, dimmed and marked Gone.

### Explore and organize

- Travel between Board spaces through doors, portals, or other Space actions. Other spaces keep running while you're away.
- Drop a stack onto a portal to send it to the destination's first free compatible cell without following it. A full destination leaves your stack where it was.
- Open Inventory directly or through an Inventory action item. Drop a stack onto that item, or press `I` while dragging, to store it. Storage restrictions still apply.
- Click an Inventory item to take out its whole stack. It goes to the current Board, then the Toolbar if allowed and needed; it doesn't activate or start production.
- Drag, swap, stack, and merge items. Merge direction matters: dropping a tool onto a resource can do something different from dropping the resource onto the tool.
- `Shift + left click` splits a Board stack.
- Zoom with the wheel or a pinch, pan with a right drag, and press `0` to reset the view. A ghost marks where your dragged item came from.

### Sound and desktop

- Listen to a random Music playlist with crossfades and sound effects for production, item interactions, and other events. An item can play its own music while its detail is open; closing it resumes the background track where it left off.
- Adjust Master, Music, and SFX volumes separately in Sound settings. Changes apply immediately and are remembered.
- Choose your window mode or toggle fullscreen with `F11` or `Alt + Enter`. Web links open in your browser.
- Enable cheats in Game settings to test things, including Speed up. It speeds up the whole simulation, including expiry, without instantly finishing work.
- Play on macOS, Windows, or Linux. macOS requires Ventura 13 or newer.

## Gameplay engine

These are the building blocks you can use when making a game.

### Items, production, and time

- Combine production lines, limited Units, directional merges, and Clock timers on one Item. An immediate Space or Inventory action can replace production lines.
- Set recipe requirements, consumed or borrowed materials, unit costs, duration, queue size, and separate manual and automatic defaults. Inputs hold only the required maximum and close while their line is running.
- Use rules to control availability. A Limit condition checks whether an item has reached its global maximum, so a rule can disable a line or suppress a drop until stock falls again. It counts existing items, not promised outputs. Clock rules can pause both its interval and lifetime; missed pulses don't pile up or switch to another recipe.
- Give items a lifetime, a repeating interval, or both. Returning from storage doesn't create catch-up production. If completion and expiry happen together, completion goes first.
- Choose Loose-kill to wait for eligible work and safe returns, or Kill switch to cancel work and discard anything that cannot fit. Expiring material also settles an exhausted producer's depletion and returns its borrowed items.
- Work reserves its possible outputs when it starts, so several producers can't overbook the same item limit. Queued requests reserve nothing.

### Outputs, placement, and merges

- Create fixed outputs, quantity ranges, and weighted alternative sets. Rules filter the sets before one is selected. Its Guaranteed groups include every drop; each Chance group makes one shared probability check for all its drops. Separate Chance groups are independent, and rejected drops never trigger a replacement draw.
- Restrict items to Board, Inventory, or Toolbar, or allow all three. Flexible outputs and returns try their origin's storage first, then the other allowed surfaces. They never spill into another Board space.
- Choose nearby or random Board placement. Compatible stacks fill before empty cells; items carrying work, timers, or other individual state stay separate. Each cell or slot holds one item stack.
- Let rules inspect the local Board, shared storage, or every space. Where a rule can look is separate from where an item can be stored.
- Define what a merge does to each side: use, consume, spend a unit, keep, remove, or replace, with optional output. Replacements get their own fresh timers.

### Consistent results

- The simulation uses fixed time steps and repeatable random results. A blocked output won't get a luckier roll just because it retries later.
- Ordinary actions either finish completely or leave things unchanged. Full storage holds completed work for retry; forced removal is the explicit exception that can discard items.
- Sounds follow completed actions. Expiry, depletion, and disappearing without a replacement can have distinct cues. Animations and audio don't decide whether work succeeds.
- Saves keep your items, spaces, queues, deliveries, timers, and work in progress. A fatal error stops play, preserves the result of the last completed action, and keeps a diagnostic report.

## For game authors

### Make and test your game

- Create a project, open its folder directly, or import a Serapack. Project, Items, Artwork, Music, SFX, Board, Notes, MCP, and Build are all in the Editor.
- Build Items from optional capabilities and configure starting stacks, spaces, storage, rules, recipes, outputs, and timers. Forms point out invalid fields and protect unsaved edits.
- Search large catalogs, mark drafts, and use consistent section shortcuts across Editor detail pages and edit forms. Draft is just an authoring label: draft items still run and enter builds.
- New Item IDs follow their titles and remain editable. Duplicate recipes, inputs, rules, and output branches to save typing; copied recipes get fresh IDs without taking over the manual or Clock default.
- Save with `Cmd + S` or `Ctrl + S`. Renaming an Item updates its references; deletion shows you what depends on it first.
- Test in the real game through the Editor Board, including audio, Inventory, and cheats. Switch spaces freely or try Speed up. Reset starts from your saved project; test sessions aren't saved into it.
- Use Connections to see where items come from and where they're used. Chain explores merge and Clock outcomes. Estimate gives optimistic time and resource costs, including random outputs and shared requirements. For actual runtime behavior, use the Board.
- Keep Markdown Notes linked to Items and resources. Find the same Notes from the project or relevant detail pages; they stay out of the published game.

### Add art and audio

- Import square PNG Artwork for Items and separate Images for the launcher and shell. Browse previews, check usage, create an Item from Artwork, and rename or delete resources.
- Scale Item artwork from 25% to 100% without changing its tile size. You can layer its default composition; switching between authored images based on progress is not supported yet.
- Give each production line optional Artwork for its Editor preview and the Game's Lines and Queue. Lines without it show no placeholder.
- Optimize Artwork losslessly when you choose. Builds resize it to at most 256 × 256; shell Images keep their original size and bytes.
- Import and preview Music and SFX in their own libraries. Ogg/Opus is the stored format; converting other supported audio needs `ffmpeg` on your PATH. Conversion trims silence at the edges and keeps internal pauses.
- Select tracks for the random playlist and optionally choose a Music track for each Item Detail. Both kinds of references include the track in the build; unreferenced Music stays in your project.
- Rename Music and SFX with readable display names without breaking their references. Search by name, preview tracks, and inspect usage before deletion; the audio keeps its stable identity.
- Assign one SFX per event, including queueing, production, placement, merging, portal transfers, swaps, rejected drops, expiry, depletion, disappearance, and opening or closing Item Detail. Unassigned events stay silent. Grouped event pickers, filters, and badges show what is connected.
- Use SFX Optimize to trim silence from existing effects. Already clean effects aren't re-encoded.

### Keep it portable

- Your project is ordinary JSON and resource files: `project.json`, `game.json`, `items/<uid>.json`, `artwork/`, `image/`, `music/`, `sfx/`, and `notes/`. Generated JSON Schema helps external tools edit it too.
- Items keep an immutable UID alongside their editable ID. Resource IDs are unique across all resource types.
- Save only changed data, export a fresh project copy, and use Git for history. Serakki preserves unrelated files in your project folder.
- Choose the output version yourself in Build. Publish one self-contained Serapack with `Save as...`, or install it locally. Updates don't silently delete your save.
- Build uses saved files, keeps its result when you navigate away, and tells you when later edits have made that result outdated. It packs the resource bytes it validated, even if source files change during the build. Editor and CLI builds use the same validation and packing process.

## AI-assisted authoring

- Connect an AI through the project's MCP server, locally or through an optional OAuth-protected ngrok endpoint. You can also run it without the GUI using `serakki-cli editor mcp <projectId>`.
- Let it inspect Items, Artwork, Notes, relationships, Chain, Estimate, and validation; create and edit Items; adjust layouts and starting items; or manage Notes.
- Tools expose the same schemas and saved project used by the Editor, check revisions, and can preview deletion impact. Run the GUI or headless MCP for a project, not both at once.

## Loading, saves, and troubleshooting

- Serapacks bundle the game and its resources without executable code. Official packages carry a signature verified offline; Community packages are playable too.
- Loading, importing, and building stream resources as needed. Music supports seeking, and unused game textures are gradually released so a long session doesn't keep every image you've seen in memory.
- Saves are separate `.serasave` JSON files. Serapacks use the `.serapack` extension. Packages and images are validated before use; resource imports guard against filename collisions and accidental replacement with a different resource type.
- Project writes are best-effort across multiple files: an interrupted save may leave some changes written. There is no whole-project rollback.
- The macOS CLI can validate and pack games, verify Serapacks, generate schemas, and run MCP. Replay and diagnostic slicing help investigate failures without touching installed saves.
- Desktop downloads include macOS Apple Silicon DMG/ZIP, Windows x64 installer/ZIP, and Linux x64/arm64 AppImage, plus checksums and a standalone Serapack.

## Before opening an older project

0.5.0 is still pre-stable. Serakki reads only the current project, Serapack, and save formats. Projects, `.arkpack` packages, and `.arksave` saves from earlier Arkini builds are not supported; there are no compatibility readers or automatic migrations. Recreate older development data in the current format. Compatibility checks use major versions, but a matching major does not make an obsolete format readable.

Serakki stores local projects, installed packages, saves, preferences, and diagnostics under `~/.serakki`. It does not load the former `~/.arkini` directory. The bundled game is named Serakki and uses the package ID `serakki`.

- Projects now start at `project.json`, with one Item format under `items/<uid>.json`. Charges became Units; temporary lifetime and scheduled production became Clock capabilities.
- Artwork, Images, Music, and SFX use their own root folders. The old `assets/` and `resources/` layout is obsolete. Each Music/SFX file now needs a matching JSON file with its display name; filenames hold stable IDs. Serapacks omit those names and use JSON metadata with raw resources; saves use JSON instead of MessagePack.
- Outputs select one weighted set containing Guaranteed or Chance groups. Older nested or repeated weighted-roll shapes are no longer supported.
- Item types, categories, tags, layered Board occupancy, and progress-based selection of artwork aren't part of the current model.
- Built-in project history, named Board scenarios, the Flow workspace, and embedded ChatGPT were removed. Use Git, Board testing, Connections/Chain/Estimate, and MCP for those workflows.

A stable data-compatibility guarantee will begin with an explicitly announced stable baseline.
